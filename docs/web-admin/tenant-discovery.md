# 动态租户发现与确认导入

## 1. 功能说明

动态租户发现用于从已登记的控制库读取租户清单，并将选中的租户登记到 meteor-forge 管理元数据库。发现和导入是两个明确分离的步骤：预览只读，导入必须由管理员确认。

## 2. 控制库约定

发现功能通过已登记的数据源连接控制库，读取 t_tenants 表：

- 必需列：tenant_id、dsn、status。
- 可选列：driver。
- 只读取 status = 'active' 的记录。
- 查询超时为 10 秒。
- 控制库数据源凭据保存在管理元数据库中，API 不返回 DSN。

若现有控制库结构不符合约定，应先显式适配表名和字段，不要假定系统会自动识别任意租户表结构。

## 3. Web 操作流程

1. 在「数据源管理」中登记控制库数据源。
2. 进入「多租户管理」，点击「发现并导入租户」。
3. 选择已登记的控制库数据源，点击「读取发现预览」。
4. 检查控制库租户 ID、可选驱动、建议名称/标识以及本地重复提示。
5. 为每条待导入记录选择已登记的目标数据源；若控制库提供 driver，目标数据源驱动必须一致。
6. 勾选本批次需要导入的记录。
7. 点击「确认导入」，并完成二次确认。

成功后租户列表自动刷新，创建动作写入租户生命周期审计。

## 4. API

预览：

GET /api/v1/tenant-discovery/preview?data_source_id={control-data-source-id}

响应只包含控制库租户 ID、可选驱动、建议名称/标识和本地是否已存在同标识租户。不会返回 DSN，也不会修改数据。

确认导入：

POST /api/v1/tenant-discovery/sync

请求示例：

~~~json
{
  "control_data_source_id": "control-source-id",
  "confirm": true,
  "items": [
    {
      "control_tenant_id": "tenant-a",
      "name": "Tenant A",
      "code": "tenant-a",
      "data_source_id": "registered-target-source-id"
    }
  ]
}
~~~

服务端会重新读取控制库，确认所选租户仍为 active，并验证每个目标数据源已登记；若控制库提供 driver，还会校验目标驱动一致。批量导入在管理元数据库事务中提交，并为每个新租户写入生命周期审计记录。

## 5. 限制与安全边界

- 只有 administrator 可预览和执行同步。
- 控制库 DSN 仅用于发现查询，不回传 API、不写入日志，也不会复制到新租户。
- 租户目标数据源必须预先登记并加密保存。
- 同步只创建本地租户；遇到重复标识时整批回滚，不覆盖已有租户。
- 不自动删除、不自动停用、不自动修改已有租户。
- confirm 必须为 true，每批最多 500 条。
- 控制库结构必须符合约定格式；结构不一致时应先显式适配。
- 控制库状态变化、目标数据源失效或标识冲突时，服务端会拒绝整批导入；刷新预览并重新核对后再提交。

## 6. 现有租户和迁移

发现结果不会自动替换现有租户。管理员应先核对本地重复标识，再决定是否修改映射或取消导入。

导入后，租户可以按普通租户执行连接测试和迁移。租户迁移的作用范围仍是映射的数据源；多个租户共用同一数据源时共享迁移历史。详见中文用户手册和 API 详细说明。
