# 操作审计

操作审计页面汇总迁移与分片 DDL 的状态事件，按发生时间倒序排列。支持按操作类型、目标状态、任务、数据源、租户、分片规则和时间范围筛选，并通过分页读取历史记录。

## API

`GET /api/v1/audit-events`

查询参数：

| 参数 | 默认值 | 约束 | 说明 |
|---|---:|---|---|
| kind | 空 | `migration` / `shard_ddl` | 操作类型 |
| status | 空 | queued / running / succeeded / failed / canceled / interrupted | 事件目标状态 |
| task_id | 空 | 最长 128 字符 | 精确匹配任务 ID |
| data_source_id | 空 | 最长 128 字符 | 精确匹配数据源 ID |
| tenant_id | 空 | 最长 128 字符 | 精确匹配租户 ID，仅匹配迁移事件 |
| shard_rule_id | 空 | 最长 128 字符 | 精确匹配分片规则 ID，仅匹配分片 DDL 事件 |
| from | 空 | RFC3339 时间戳 | 起始时间，包含边界 |
| to | 空 | RFC3339 时间戳 | 结束时间，包含边界 |
| limit | 50 | 1–200 | 每页数量 |
| offset | 0 | 0–10000000 | 零起始偏移量 |

`from` 和 `to` 可携带时区偏移；服务端会转换为 UTC。若同时提供，两者必须满足 `from <= to`。

响应：

```json
{
  "items": [],
  "total": 0,
  "limit": 50,
  "offset": 0
}
```

事件字段包括任务 ID、类型、数据源、租户或分片规则、动作、状态变化、操作者标记、请求来源、说明和发生时间。分片 DDL 事件额外提供源表与目标表名称。查询只读管理元数据库，不会访问或修改目标数据库。

## 身份边界

任务审计记录已保存真实登录用户名；请求来源取管理 API 看到的直接远端地址，不信任转发头。认证事件与管理员账号生命周期事件单独保存在 `admin_security_audit_events`，仅 administrator 可通过 `GET /api/v1/auth/security-events` 查询。管理 API 必须继续绑定 loopback，不得暴露公网。


## 批量租户迁移批次审计

批量租户迁移会在提交第一个子任务前创建持久化批次记录，并写入 `submission_started` 事件。所有租户的子任务提交完成后，服务端在同一 SQLite 事务中保存成功入队数量、提交失败租户清单和 `submission_completed` 审计事件。

- 即使全部子任务都未能创建，批次记录仍可通过 `GET /api/v1/tenant-migration-batches/{id}` 查询，不会因没有子任务而丢失。
- 批次记录保存发起账号、请求来源、租户总数、成功入队数、提交失败数和失败摘要。
- 批次级审计事件与提交结果更新原子提交；审计写入失败时，批次状态保持 `submitting`，不会产生“已审计完成”的假状态。
- 批次查询同时返回批次级审计事件和子任务状态/失败详情。提交阶段失败与任务执行阶段失败分别统计。
- 任务失败消息使用通用摘要，不保存 DSN、SQL、密码或驱动原始错误。


## 租户生命周期审计

租户创建、更新和删除都会在管理元数据库事务中写入独立的 `admin_tenant_audit_events` 记录。审计事件保存动作、操作者、请求来源、发生时间和变更前/后的非敏感快照（租户名称、code、数据源 ID、状态）。

- 租户变更与对应审计事件原子提交；审计写入失败时，创建/更新/删除操作全部回滚。
- 删除事件保留删除前快照，审计记录不依赖租户主表外键，因此租户删除后仍可查询历史。
- `GET /api/v1/tenants/{id}/audit` 支持分页，供所有已认证角色只读查看。
- 快照不包含 DSN、密码、SQL 或其他连接凭据。
