# Web 管理后台用户手册

本文面向日常使用 meteor-forge Web 管理后台的开发、DBA 和运维人员。本文只描述当前代码已实现的功能；自动故障隔离和远程公网部署不属于当前版本能力。租户定时巡检已提供配置与运行状态管理，默认关闭，必须由管理员显式启用。

## 1. 产品组成与工作边界

meteor-forge 由三部分组成：

- **Go 核心库**：提供数据库迁移、驱动适配、多租户解析和分库分表能力，位于 `pkg/`。
- **CLI**：独立执行 SQL 迁移、批量租户迁移和管理元数据库备份。
- **Web 管理后台**：通过 Go HTTP API 管理已登记的数据源、租户、迁移任务、分片规则和审计记录。

Web 管理后台使用独立 SQLite 管理元数据库保存控制面配置。被管理的 MySQL、PostgreSQL、SQLite、ClickHouse 数据库称为目标数据源。管理元数据库与目标数据库不是同一个概念，备份管理元数据库不会备份业务数据。

## 2. 启动与首次登录

### 2.1 编译或启动 API

在仓库根目录执行：

```bash
go build -o meteor-forge-server ./cmd/server
```

首次启动前准备加密密钥和管理员初始密码：

```bash
export METEOR_ADMIN_ENCRYPTION_KEY="$(openssl rand -hex 32)"
export METEOR_ADMIN_BOOTSTRAP_PASSWORD='替换为至少 12 位的强密码'
# 可选：默认管理员用户名为 admin
export METEOR_ADMIN_USERNAME='admin'
./meteor-forge-server
```

也可以使用 `go run ./cmd/server`。首次初始化成功后，管理员账号保存在管理元数据库中。后续启动不再使用 bootstrap 密码重置已有管理员密码；修改密码应登录后台操作。

默认 API 地址为 `127.0.0.1:8081)。服务强制 loopback 监听，非本机地址会被拒绝。健康检查地址为 `http://127.0.0.1:8081/api/v1/health`。

### 2.2 启动前端

另开终端：

```bash
cd web/admin
npm install
npm run dev
```

打开 Vite 输出的本地地址，默认通常为 `http://127.0.0.1:5173`。开发服务器将 `/api` 请求代理到 Go API。生产部署方式应由部署环境提供受控的静态资源托管；当前服务端本身提供的是 API，不应据此推断它已内置静态文件托管。

输入首次创建的管理员账号和密码登录。

## 3. 管理界面导航

| 页面 | 用途 |
|---|---|
| 总览 | 查看管理控制台入口和概览信息 |
| 数据源管理 | 登记、编辑、删除和测试目标数据库连接 |
| 迁移管理 | 查看迁移版本、生成 Dry Run、提交 Up/Down/版本跳转任务 |
| 多租户管理 | 创建和维护租户映射、测试连接、查看生命周期审计、发现并导入租户 |
| 分库分表 | 维护分片规则、预览路由、盘点物理表、检查表是否存在、预览/提交结构克隆 |
| 执行任务 | 统一查看迁移与分片 DDL 任务、进度、结果和任务审计 |
| 操作审计 | 按任务类型、状态、时间及资源筛选操作记录 |
| 管理员管理 | 管理员账号和角色管理，仅管理员可见 |
| 安全审计 | 查看登录、登出、密码和管理员账号生命周期事件，仅管理员可见 |

前端会根据角色隐藏无权操作，但真正的权限检查由后端执行。不要通过手工调用接口绕过权限边界。

## 4. 数据源管理

1. 打开「数据源管理」，选择新增数据源。
2. 填写显示名称、驱动类型和 DSN。
3. 支持驱动：`mysql`、`postgres`、`sqlite`、`clickhouse`。
4. 保存后使用连接测试确认目标数据库可访问。
5. 列表和详情只返回数据源元信息，不会回显 DSN。

DSN 通过 AES-256-GCM 加密后存入管理元数据库。请勿将 DSN 写入工单截图、日志或代码仓库。已有租户或分片规则引用的数据源存在生命周期保护；存在活动迁移任务的数据源也不能随意修改或删除。遇到 HTTP 409 时，先检查引用关系和活动任务，不要直接修改元数据库绕过保护。

## 5. 迁移管理

### 5.1 准备迁移脚本

在服务端配置的迁移目录中按版本命名脚本：

```text
migrations/
  20261106001_create_orders.up.sql
  20261106001_create_orders.down.sql
```

文件名格式为 `{version}_{description}.up.sql` 和 `{version}_{description}.down.sql`。Up 脚本必须存在；缺少 Down 脚本的版本不可正常回滚。迁移脚本由管理 API 所在机器读取，不是从浏览器上传。

### 5.2 查看状态和预览

1. 打开「迁移管理」并选择数据源。
2. 刷新迁移状态，检查已应用和待执行版本。
3. 点击「生成 Dry Run」查看计划、动作、Down 是否存在及 SHA-256。
4. 若已应用脚本的校验和与本地文件不一致，服务端会拒绝预览/执行。应先核对历史版本，不要直接改写已应用脚本。

注意：状态查询或预览可能会在目标数据库创建迁移历史表 `schema_migrations`；它们不会执行用户迁移脚本中的 SQL。

### 5.3 提交任务

- **Up**：迁移操作员或管理员可提交。执行前确认目标库备份、脚本内容和目标数据源。
- **Down / DownSteps / ToVersion**：仅管理员可提交，必须显式确认。回滚和版本跳转具有破坏性，执行前必须完成目标数据库备份。
- **租户迁移**：在租户详情中提交单租户 Up；也可批量提交多个租户 Up。批量每次 1–100 个租户，只支持 Up。
- 同一数据源的迁移任务串行执行；不同数据源的批量租户任务有并发上限。
- 任务取消不等于数据库回滚。已经成功完成的迁移步骤不会自动撤销。

在「执行任务」查看排队、执行、成功、失败、取消或中断状态。服务重启后遗留的 queued/running 任务会标记为 interrupted，不会自动重放。失败后应先检查数据库实际结构和迁移历史，再决定是否重新提交。

**租户迁移语义：** 租户 ID 用于校验、任务归属和审计。当前迁移仍在租户映射的数据源上执行数据库级 SQL，不会自动按租户过滤 SQL。映射到同一物理数据源的租户共享迁移历史表，因此同一物理数据库上的迁移只会应用一次。

## 6. 多租户管理

### 6.1 手动创建租户

在「多租户管理」创建租户，填写名称、唯一 code、已登记的数据源和状态。code 会归一化为小写，只允许字母、数字、短横线和下划线。租户通过 data_source_id 引用数据源，不重复保存 DSN。

状态为 active 或 suspended。停用租户会阻止租户解析和新的租户迁移任务，但不会删除目标数据库或数据。

### 6.2 连接测试与健康巡检

租户列表提供单租户「测试连接」和批量「巡检」：
1. 单个巡检可在对应租户行触发；批量巡检先勾选运行中的租户，再点击「批量巡检」。
2. 每批最多 100 个租户，最多 4 个并发，每个连接最多等待 5 秒。
3. 列表展示最近一次结果、巡检时间和耗时；状态分为连接正常、连接异常和未巡检。
4. 所有已登录角色可读取巡检状态，只有管理员可以触发单个或批量巡检。
5. 最新状态保存在管理元数据库；每次手动或定时巡检也会追加一条独立历史记录。
6. 在「多租户管理」页面的「定时巡检」区域，管理员可启用或关闭全局定时巡检，并配置巡检间隔（30–86400 秒）、单租户超时（1–30 秒）和历史保留天数（1–365 天）。默认关闭；只有显式启用后才会定时访问目标数据库。
7. 定时巡检区域会展示当前进程的执行轮次、成功/失败次数、最近开始与成功时间、预计下次执行时间和最近耗时；可手动刷新运行状态。统计在服务重启后归零，不能代表多实例全局数据。最近错误只显示脱敏摘要。
8. 所有已认证角色可查看定时巡检配置和历史；只有管理员可修改配置。历史列表支持租户、结果、来源和时间范围筛选，并可加载更多记录。 点击任意历史记录右侧的「查看详情」，可在详情抽屉中查看记录 ID、租户名称与标识、目标数据源、巡检来源、检查时间（本地和 UTC）、执行耗时及完整的已保存结果摘要。结果摘要按安全规则归一化，不包含 DSN、密码或数据库驱动原始堆栈；详情展示的是巡检记录实际持久化的内容，不会重新连接目标数据库。
9. 定时巡检只检查 active 租户，最多 4 个并发；单轮完成后才会安排下一轮。服务关闭会取消当前轮次。因取消或关闭而中断的检查不会写入失败历史或覆盖最近一次有效状态。

巡检失败不会自动停用租户、修改租户映射或执行修复。失败信息经过归一化，不回传驱动原始错误、DSN 或密码。该功能复用数据源连接池，不会为每个租户创建独立连接池。历史记录按配置保留天数清理；当前调度器为单实例进程内调度，不提供多实例选主。

租户健康概览展示当前正常、异常、未巡检租户数，以及最近 24 小时的检查次数、成功次数、失败次数和成功率。当前状态按每个租户最新结果计算；24 小时指标按检查历史次数计算，时间窗口两端均包含。没有检查记录时成功率显示为 0%。 租户列表同时展示「连续失败」和「最近成功」：连续失败从最近一条成功记录之后开始计数，成功检查会将计数重置为 0；相同检查时间按记录 ID 确定先后。由于历史记录按保留天数清理，失败次数只反映当前保留范围；显示「保留范围内无成功记录」不代表租户从未成功，只表示当前保留数据中没有成功记录。

租户管理页新增「巡检趋势」，可切换最近 24 小时和最近 7 天。健康趋势 API 同时提供最近 24 个完整 UTC 小时和最近 7 个 UTC 日历日两种统计范围，分别固定返回 24 个小时桶和 7 个日桶。无巡检记录的时间桶会补零；24 小时趋势不包含当前尚未结束的小时，7 日趋势包含截至查询时刻的今天，最后一个日桶可能只有部分数据。趋势统计来自历史记录，与当前租户状态概览是不同口径。

点击包含异常次数的柱形，可直接将下方「巡检历史」筛选为该 UTC 小时或 UTC 日内的异常记录；时间区间左闭右开，客户端会将历史接口的包含式结束时间精确设为下一个桶起点前 1 纳秒，避免相邻时间桶重复命中。没有异常次数的时间桶不可点击。切换趋势范围会丢弃旧范围的图表数据，只有最新请求可以更新图表；请求失败会显示错误提示并清空旧数据，避免将旧范围误认为新范围。历史筛选同样只接受最新请求结果；筛选无匹配记录时显示空列表，可通过清除时间、结果、来源或租户条件恢复完整历史。

在窄屏下，趋势图保留可横向滚动的完整时间桶，历史筛选控件改为纵向排列，避免挤压或溢出。

租户创建、更新和删除会与生命周期审计记录在同一事务中提交。删除租户登记不会删除目标数据库；删除后仍可通过租户审计查询历史。

### 6.3 动态发现与确认导入

1. 先将控制库作为数据源登记。
2. 打开「多租户管理」并点击「发现并导入租户」。
3. 选择控制库数据源，读取预览。
4. 检查控制库 tenant_id、驱动、建议名称/code 和本地重复提示。
5. 为每条记录映射一个已登记的目标数据源。
6. 选择要导入的项目，点击确认并完成二次确认。

发现读取控制库约定的 `t_tenants` 表，必需列为 `tenant_id`、`dsn`、`status`，可选列为 `driver`；仅发现 active 记录。导入时服务端会重新读取控制库并重新校验目标数据源。每批最多 500 条，必须显式确认。流程只创建本地租户，不导入外部 DSN，不覆盖已有租户，不会自动停用或删除租户。冲突时整批回滚。

## 7. 分库分表

支持按年、季度、月、ISO 周、旬、ID 哈希和 ID 范围七种策略。规则只保存在管理元数据库中，不会因创建规则自动创建物理表。

1. 在「分库分表」创建规则，选择已登记数据源、逻辑基础表和策略参数。
2. 使用路由预览检查时间或 ID 对应的物理表名。
3. 使用物理表盘点查看目标库中符合命名规则的表。
4. 使用表存在检查确认某个目标表是否存在。
5. 需要复制结构时先执行克隆预览，检查源表、目标表和生成的 DDL。
6. 确认后提交结构克隆任务，并在「执行任务」跟踪结果。

克隆仅复制结构，不复制数据；不会覆盖已存在的目标表，也不提供 DROP 或自动清理。不同数据库的克隆语义不同，尤其 SQLite CTAS 不会复制主键、约束、索引和触发器。生产使用前必须阅读 [管理 API 文档](../api/README.md) 中的驱动差异说明，并在目标库验证结果。

## 8. 操作审计与安全审计

- 「操作审计」记录迁移与分片 DDL 任务状态变化、操作者、请求来源和时间。
- 「多租户管理」内的租户审计记录创建、更新、删除前后的非敏感快照。
- 「安全审计」记录登录成功/失败、登出、密码变更和管理员账号创建、角色变更、删除。
- 审计数据保存在管理元数据库。不要把审计记录视为目标业务数据库的备份。

## 9. 备份与恢复

管理元数据库包含加密 DSN、管理员、租户映射、任务和审计数据。使用 CLI 在线备份：

```bash
./meteor-forge metadata-backup --to /secure-backup/admin-20261106.db
```

命令使用与 Web 服务相同的 `METEOR_ADMIN_DB` 和 `METEOR_ADMIN_ENCRYPTION_KEY` 配置。备份文件不覆盖已有文件，并执行完整性检查。恢复必须先停止服务，并使用备份时相同的加密密钥。详细步骤见 [备份与恢复手册](backup-restore.md)。

该备份**不包含目标 MySQL、PostgreSQL、SQLite 或 ClickHouse 数据库**。目标数据库必须单独备份。

## 10. 当前限制与常见问题

- 管理 API 当前仅允许 loopback 监听；不支持直接公网暴露或未经设计的反向代理部署。
- 租户连接健康支持手动和可配置的定时巡检，并提供巡检历史筛选与游标分页；当前不提供多实例分布式调度、外部告警、自动故障隔离或自动修复。
- 当前没有自动修复、自动停用故障租户或自动执行回滚的功能。
- 管理元数据库密钥丢失后，已存储 DSN 无法解密；必须单独安全保管密钥。
- 任务显示 interrupted 时，不代表数据库完全未变更；应检查目标数据库实际状态。
- API 返回 401 时检查登录会话；403 表示当前角色无权执行；409 通常表示资源引用、活动任务或状态冲突；不要绕过这些保护直接修改数据库。
- CLI 和 Web 管理 API 是不同入口：CLI 迁移参数见仓库根目录 README；Web 管理 API 环境变量见 [部署与运维手册](deployment.md)。
