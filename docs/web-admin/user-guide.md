# meteor-forge Web 管理后台用户手册

## 1. 产品组成

meteor-forge 当前包含三类能力：

- CLI：独立执行数据库迁移、查看迁移状态、生成迁移脚本、批量租户迁移和管理元数据库备份。
- Go 核心库：可嵌入 Go 服务，提供迁移、数据库驱动、租户路由和分片能力。
- Web 管理后台：通过浏览器管理数据源、租户、迁移任务、分片规则、物理分片表和审计记录。

Web 管理后台由 Vue 3 前端和 Go HTTP API 组成。管理元数据库使用 SQLite；目标数据库由管理员登记，可为 MySQL、PostgreSQL、SQLite 或 ClickHouse。

## 2. 首次启动

### 2.1 环境要求

- Go 版本满足 go.mod 声明的版本要求。
- Node.js 和 npm：用于构建 Vue 管理界面。
- 目标数据库驱动所需的网络访问和数据库账号权限。
- OpenSSL（推荐）：用于生成管理元数据库加密密钥。

### 2.2 生成密钥并启动 API

Linux/macOS：

~~~sh
export METEOR_ADMIN_ENCRYPTION_KEY="$(openssl rand -hex 32)"
export METEOR_ADMIN_BOOTSTRAP_PASSWORD='请替换为至少12位的强密码'
go run ./cmd/server
~~~

Windows PowerShell：

~~~powershell
$env:METEOR_ADMIN_ENCRYPTION_KEY = (openssl rand -hex 32)
$env:METEOR_ADMIN_BOOTSTRAP_PASSWORD = "请替换为至少12位的强密码"
go run ./cmd/server
~~~

首次启动时，服务使用 METEOR_ADMIN_USERNAME 创建管理员；未设置时用户名默认为 admin。首次管理员创建成功后，后续重启不会再使用启动环境变量重置密码。

默认 API 地址为 http://127.0.0.1:8081。健康检查：

~~~sh
curl http://127.0.0.1:8081/api/v1/health
~~~

预期返回 JSON，status 为 ok。健康检查不代表目标数据库连接成功。

### 2.3 启动前端

~~~sh
cd web/admin
npm install
npm run dev
~~~

打开 Vite 输出的本地地址，默认 http://127.0.0.1:5173。开发代理将 /api 请求转发到本地 Go API。若 API 不在默认地址，可通过 METEOR_ADMIN_API 设置代理目标，具体以 web/admin/vite.config.ts 为准。

登录时使用首次启动创建的管理员用户名和密码。浏览器会话使用 HttpOnly Cookie，不需要也不应该把 token 复制到 localStorage。

## 3. 管理员与角色

系统角色：

| 角色 | 能力 |
|---|---|
| administrator | 完整管理权限；可管理数据源、租户、分片规则、管理员账号，执行迁移回滚及分片 DDL |
| migration_operator | 查看资源并提交获准的 Up 迁移任务、取消迁移任务；不能执行回滚或管理账号 |
| shard_operator | 查看资源、预览分片路由、执行获准的物理表结构克隆及取消分片 DDL 任务 |
| viewer | 只读查看；不能提交变更任务 |

后端 API 会再次校验权限。前端隐藏按钮只是交互提示，不能替代服务端授权。角色具体接口规则见 API 接口目录与权限矩阵。

管理员可在「管理员管理」页面创建账号、调整角色和删除账号。密码至少 12 个字符。角色变更或账号删除会撤销目标账号的现有会话；不能删除或降级最后一个管理员。

## 4. 数据源管理

进入「数据源管理」：

1. 点击新增数据源。
2. 输入便于识别的名称。
3. 选择 mysql、postgres、sqlite 或 clickhouse 驱动。
4. 输入对应驱动的 DSN。
5. 保存后使用连接测试确认连通性。

安全注意：

- DSN 只在创建/更新时提交，服务端使用 AES-256-GCM 加密保存。
- 列表、详情和测试响应不返回 DSN。
- 编辑时必须提交新的完整 DSN；旧 DSN 不会回显。
- 被租户引用的数据源不能修改连接配置或删除。先调整租户映射。
- 删除数据源登记不会删除目标数据库或其中的数据。

连接测试使用短超时。失败响应为通用提示，不应从中推断数据库驱动的原始错误细节。

## 5. 租户管理

进入「多租户管理」：

1. 创建租户并填写名称、唯一 code。
2. 选择一个已登记的数据源。
3. 状态可设为 active 或 suspended；新租户默认 active。
4. 保存后可测试租户连接、查看生命周期审计。

租户 code 会归一化为小写，只允许字母、数字、短横线和下划线，并且全局唯一。租户记录只引用 data_source_id，不重复保存 DSN。

### 5.1 租户连接测试

点击租户行的连接测试，系统通过租户关联的数据源连接池执行 Ping，超时为 5 秒。测试失败不会自动停用租户，也不会修改租户状态。

### 5.2 租户生命周期审计

租户详情中的审计入口可查看创建、更新和删除事件。事件包含操作者、请求来源、时间及变更前后非敏感快照，不包含 DSN 或连接凭据。删除租户后历史审计仍保留。

### 5.3 动态发现与导入

适用于控制库已有租户登记、希望将其导入 meteor-forge 管理元数据库的场景：

1. 先在数据源管理中登记控制库数据源。
2. 在多租户管理页面点击「发现并导入租户」。
3. 选择控制库数据源并读取预览。
4. 检查发现的租户 ID、驱动和本地重复提示。
5. 为每个待导入租户选择已登记的目标数据源。
6. 勾选本批次项目并确认导入。

发现约定读取控制库 t_tenants 表的 tenant_id、dsn、status 列，可选 driver 列；仅 active 记录参与预览。控制库 DSN 只用于发现查询，不会被回传或导入。目标数据源必须事先登记。每批最多 500 条，重复 code 会使整批回滚。该流程只创建本地租户，不删除、覆盖或自动停用已有租户。

详见动态租户发现文档。

## 6. 数据库迁移

### 6.1 准备迁移脚本

由服务端 METEOR_MIGRATIONS_DIR 指定脚本目录，默认是当前工作目录下的 migrations。文件名格式：

~~~text
{version}_{description}.up.sql
{version}_{description}.down.sql
~~~

Up 脚本必须存在；缺少 Down 脚本的版本不能回滚。迁移脚本应纳入版本控制，并在执行前经过代码审查和目标环境验证。

### 6.2 查看状态与预览

在「迁移管理」选择数据源，查看已应用和待执行版本。Dry Run/预览用于查看待执行计划，不会执行用户迁移 SQL。

注意：当前迁移驱动的历史表初始化可能创建 schema_migrations 表。因此首次读取状态或预览并非对目标数据库完全零写入；它不会执行用户迁移脚本中的 DDL/DML。

### 6.3 提交迁移任务

Up 任务以异步方式提交，可在「执行任务」页面查看排队、执行、成功、失败或中断状态。任务进度反映已完成的迁移步骤，不代表单条 SQL 内部百分比。

Down、DownSteps、ToVersion 属于危险操作，仅管理员可提交，必须显式确认。执行前应备份目标数据库并核对 Up/Down 脚本。取消任务不等于回滚已经完成的迁移步骤；取消后必须检查目标库迁移历史和实际结构。

### 6.4 租户迁移

租户级迁移任务会校验租户处于 active 状态，并在其映射的数据源上执行迁移。租户 ID 用于任务归属和审计追踪；当前迁移 SQL 仍是数据库级执行，不会自动按租户过滤 SQL。

多个租户映射到同一数据源时共享 schema_migrations 记录，并按数据源串行执行；同一物理数据库上的迁移只应用一次。批量租户迁移每批 1–100 个租户，只提供 Up，不提供批量回滚。单个租户提交失败会记录在批次结果中，不阻止其他租户继续提交。

## 7. 分库分表管理

进入「分库分表」页面：

1. 创建分片规则，填写目标数据源、基础表名、分片策略及策略参数。
2. 使用路由预览输入时间或 ID，检查将命中的物理表名。
3. 使用物理表盘点查看目标数据源中已有的表，并可检查指定表是否存在。
4. 如需创建物理表结构副本，先执行克隆预览，核对源表、目标表和驱动限制。
5. 显式确认后提交克隆任务，并在执行任务页面跟踪状态。

当前支持的分片策略包括 year、quarter、month、week、ten_day、id_hash 和 id_range。时间范围预览最多十年；ID 范围和物理表数量有服务端上限。

结构克隆不复制业务数据。不同数据库驱动的复制语义不同：SQLite 的 CTAS 仅复制列结构，不复制主键、约束、索引和触发器；其他驱动也有各自限制。生产执行前必须核对预览说明，并在目标环境验证结果。不要将结构克隆理解为完整数据库迁移或数据复制。

## 8. 执行任务与审计

「执行任务」统一展示迁移任务和分片 DDL 任务。选择任务可查看详情、状态进度和审计事件。状态包括 queued、running、succeeded、failed、canceled、interrupted。

服务重启时，遗留的 queued/running 迁移任务会标记为 interrupted，不会自动重放。分片 DDL 任务也会执行中断恢复处理。不要仅凭任务失败状态直接重试：先检查目标数据库中已产生的变更。

「操作审计」用于查询迁移和分片 DDL 状态变化；「安全审计」仅管理员可查看，记录登录成功/失败、登出、密码变更和管理员账号生命周期事件。

## 9. 日常安全检查

- 确认管理 API 仅绑定 loopback，不要暴露到公网或通过反向代理转发。
- 确认管理元数据库文件和父目录权限受限。
- 将 METEOR_ADMIN_ENCRYPTION_KEY 存放在独立安全配置中，并与管理元数据库备份分开保管。
- 备份管理元数据库时，同时记录对应加密密钥的安全保管位置。
- 执行迁移、回滚和分片 DDL 前，先检查目标、预览和备份。
- 定期查看失败/中断任务与操作、安全审计记录。
- 不要把 DSN、密码、会话 Cookie 或加密密钥写入 Issue、日志或代码仓库。

## 10. 常见问题

**健康检查正常，但数据源连接失败。** 健康检查只确认管理 API 存活，不检查目标数据库。请在数据源页面单独测试连接，检查 DSN、网络、防火墙和数据库账号权限。

**登录后提示未授权。** 检查会话是否过期、Cookie 是否被浏览器拦截，以及前端是否通过同源 Vite 代理访问 API。重新登录后再试。

**数据源不能删除或修改。** 如果数据源仍被租户引用，服务端会拒绝操作。先修改或删除关联租户映射。

**租户批量迁移有失败项。** 打开批次详情查看失败租户和子任务状态。检查目标库迁移历史及实际结构后，再决定是否单独重新提交。

**迁移任务变成 interrupted。** 这表示服务重启时发现任务仍处于 queued/running。系统不会自动重放。请先检查数据库迁移历史、已执行 SQL 和任务审计。

**前端构建成功但无法直接访问 API。** 前端构建产物不包含 Go API 服务。当前 Go API 仅 loopback 监听；请使用仓库提供的本地开发代理方式，不要自行将 API 暴露到公网。
